# 快速上传与快速检索：已确认实施基线

> 状态：已确认，允许据此进入设计与实现
> 固化日期：2026-08-21
> 适用范围：新增普通子条目的草稿能力、基于单段聊天的智能草稿生成、基于单段聊天的快速检索
> 规则：本文只记录已确认决定。未写入本文的参数或实现细节仍属待定；如后续决定与本文冲突，应先更新本文。

## 1. 功能目标与明确边界

本功能增加两条彼此独立、底层可复用的能力：

1. **快速上传**：从一段客户与我方的文字聊天中提炼 0～N 条可复用知识，异步生成当前用户私有的普通子条目草稿。
2. **快速检索**：从一段文字聊天中提炼最可能需要查询的自然语言问题，同步检索用户可访问的全部知识库。

明确边界：

- 快速上传 V1 只生成“新增普通子条目”草稿。
- 不通过快速上传创建父类、主子条目或已发布内容的新修订。
- LLM 不生成、汇总或改写最终检索答案；快速检索只展示现有知识库结果。
- V1 不处理粘贴聊天中的图片，只处理文字。
- V1 不做智能草稿与已有知识或其他草稿的查重；查重属于后续增强。
- 机器人集成本期不实现，只保证核心能力不与网页或企业微信格式耦合。

## 2. 草稿不是子条目或审核提交

知识草稿是新增普通子条目正式提交前的、可变且仅创建者可见的暂存数据。它不是 `child`、`child_revision` 或 `review_submission`，因此不受正式知识实体的完整性约束。

草稿阶段的规则：

- 父类可以为空。
- 目标知识库可以为空。
- 问题、回复等业务字段可以不完整。
- 普通子条目内容字段可以在尚未选择父类时填写和编辑。
- 父类只在正式提交审核时成为必填项。
- 父类选定后，系统才加载该父类允许投稿的知识库；正式提交时至少选择一个合法知识库。

正式提交仍必须满足现有领域不变量：父类已经审核可用，且目标知识库是该父类主子条目已发布知识库的子集。

## 3. 手动草稿

只有“新增普通子条目”表单支持手动草稿。新建父类—主子条目和已有知识修订不支持草稿。

普通子条目表单提供两个明确动作：

- **暂存**：保存当前已填写内容。允许内容不完整，但至少有一个业务字段非空；字段长度、数据类型和格式等基础校验仍执行。
- **提交**：执行现有完整业务校验，并直接创建不可变审核投稿。

草稿生命周期：

- 草稿只有创建者本人可查看、编辑和删除。
- 草稿不自动过期。
- 提交失败时原样保留草稿。
- 提交成功后立即删除草稿，以正式审核投稿作为唯一后续事实来源。
- 驳回后的重新提交继续使用现有驳回记录流程，不恢复或新建草稿。
- 草稿来源由系统记录为“手动保存”或“智能生成”。来源标签只展示在创建者的草稿列表，不进入审核工作台，也不进入最终检索结果。

## 4. 会话输入与渠道适配

核心智能处理服务接收标准化消息数组，而不是企业微信原始排版。标准消息至少表达说话人、角色和正文，时间为可选信息。

渠道边界：

- 网页端负责把企业微信复制文本解析为标准化消息。
- 未来机器人可以直接组装标准化消息，不需要模拟企业微信粘贴格式。
- 一次请求只处理一个会话，但该会话可以包含多个话题。
- 企业微信网页适配器使用固定规则识别角色：说话人名称以 `融航` 开头时属于我方，其余属于客户。
- 快速上传若无法可靠解析说话人，或没有同时获得客户问题与我方回答所需的双方内容，则不生成草稿；不能让 LLM 猜测角色。

输入长度和消息数量上限由部署配置决定。网页和后端均需校验；超限时明确拒绝并提示缩小范围，禁止静默截断。

## 5. 快速上传处理流程

快速上传采用后台异步批次：

1. 用户在知识投稿页面粘贴一个会话的文字内容并发起智能生成。
2. 网页适配器解析并提交标准化消息。
3. 系统创建归属于当前用户的“处理中”批次；用户可以离开页面。
4. 后台通过 OpenAI 协议兼容接口执行内容提取。
5. 合格候选直接生成该用户私有草稿。
6. 批次完成后展示生成数量、未生成原因和失败信息。

一批聊天可以生成 0～N 条草稿：

- 如果多个问法需要同一个答案，只生成一条草稿，其他问法进入“同义问句”。
- 只有需要不同答案时才拆成不同草稿。
- 没有可复用知识时允许生成 0 条，不能为了完成任务硬凑内容。
- 一批候选允许部分成功。合格候选创建草稿，不合格候选不创建并显示原因；批次标记为“已完成，有警告”。
- 批次写入与重试必须幂等，不能因为重试产生重复草稿。

## 6. LLM 提取约束

LLM 只能做基于原会话的提炼、重组、去身份化和语言规范化，不能使用自身知识补充原文没有的事实。

内容权威规则：

- 客户发言用于提取问题、业务场景和真实问法。
- 默认只有 `融航` 人员发言可以作为回答事实依据。
- 客户先陈述、我方随后明确确认的结论可以采用，并视为经我方确认。
- 姓名、联系方式、账号、订单号、客户公司名等身份信息必须删除。
- 只沉淀可复用的通用知识。只对某个客户合同、报价、权限或定制配置成立的结论不得生成草稿；能够安全抽象时，应改写为带适用条件的通用答案。

候选最低门槛：问题与可复用回答都能从原会话获得依据。不满足门槛的候选不创建草稿，只返回未生成原因。

生成内容应脱离聊天上下文也能独立理解：

- 问题使用完整、自然的客户问法。
- 回答直接、清晰，并保留适用条件和限制。
- 删除“刚才提到的”“您这边”等上下文指代。
- 产品名、专业术语和关键业务措辞不能随意改写。

有原文依据时，LLM 可以填充以下普通子条目字段：

- 问题；
- 回复内容；
- 同义问句；
- 后续建议；
- 问题类型；
- 业务对象；
- 目的；
- 客户类型；
- 功能说明；
- 示例。

LLM 不填充或推荐以下内容：

- 父类；
- 目标知识库；
- 内部备注；
- 附件；
- 网页链接。

模型的不确定性和提取警告属于系统元数据，不得混入业务字段。智能草稿不增加“已人工核对”状态或提交门槛，满足普通提交校验即可提交。

## 7. 原始聊天留存

快速上传为了支持异步处理和失败重试，可以短期保存原始聊天文字，但必须遵守以下规则：

- 任务完成后尽快删除，最长保留 24 小时。
- 到期后物理删除。
- 应用日志、任务日志和错误日志不得记录完整聊天原文。
- 草稿不保存完整聊天记录，只保留必要的来源哈希、提取时间和模型版本等处理元数据。
- 粘贴文字只是提取输入，不自动成为知识正文、内部备注、佐证附件或网页链接。

## 8. 快速检索处理流程

快速检索位于现有知识检索页面，并采用同步交互：

1. 用户粘贴一个会话的文字内容。
2. 系统在当前请求中提取并去重查询语句，不保存原始聊天。
3. 自动对用户可访问的全部知识库执行向量检索。
4. 返回现有知识条目与佐证材料，不调用 LLM 生成最终答案。

“有价值的查询”限定为：

- 客户尚未得到明确回答的问题；
- 我方回答存在明确不确定性的问题；
- 会话中明确表示需要进一步查询的问题。

已被我方完整回答的话题、寒暄、流程性沟通和纯背景信息不单独生成查询。

查询生成规则：

- 每次生成 0～5 条自然语言查询。
- 多个问题若期望同一个答案，应先按答案目标聚类并合并为一条规范化查询。
- 答案目标不同的查询不得为了减少数量而合并。
- 超过 5 条时，优先保留客户明确提出、尚未解决且时间更靠后的问题，并提示未执行候选数量。
- 查询必须先去身份化，再执行并记录检索事件。
- LLM 不推断父类、问题类型、业务对象、目的、客户类型或其他结构化筛选条件，只生成最可能的自然语言查询。
- 用户可以编辑提取后的查询并重新检索。

结果展示规则：

- 页面顶部展示提取出的查询。
- 下方使用统一结果区域，而不是按查询重复渲染多组结果。
- 同一 `子条目修订 × 知识库` 结果只展示一次，并标注它命中了哪些查询。
- 不按回答文本去重；不同知识库的发布关系必须保留。
- 现有父类层级展示可以继续保留，但同一结果项不能因命中多个查询而重复出现。
- 没有符合条件的查询时，明确提示“未发现待查询问题”，不强行检索。

## 9. 模型接口与系统解耦

- LLM 调用统一使用可配置的 OpenAI 协议兼容接口。
- 服务地址、密钥、模型名称、超时和输入上限由部署环境配置，业务代码不绑定具体模型厂商。
- 快速上传和快速检索复用标准化会话、去身份化及 LLM 结构化输出能力，但保持独立的应用流程：快速上传异步创建草稿，快速检索同步返回结果。
- 投稿页面和检索页面分别提供入口，不创建一个混合两种动作的统一页面。
- 本期继续复用 PostgreSQL 持久任务与现有 Worker，不为该功能新增 Redis 或 RabbitMQ。

## 10. 后续事项，不纳入本期

- 智能草稿与已发布知识或其他草稿的查重、合并和修订推荐。
- LLM 自动推荐或选择父类、知识库及结构化检索筛选项。
- 从聊天图片中提取知识或查询。
- LLM 基于检索结果生成最终回复。
- 机器人渠道实现、绑定 Token 协议及机器人身份鉴权。当前仅暂定未来可由网页生成绑定 Token，再由机器人完成用户身份绑定；具体安全协议留待机器人项目设计。
- 快速检索跨查询融合排序的精确算法、各类阈值和默认输入上限。
- 单个快速上传批次允许生成的最大草稿数量。
